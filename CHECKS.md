# Checks

What runs on this repository (linters, formatters, type and test checks, git hooks, CI), every rule that is switched off and why, and the known debt, warnings and deprecations. [TESTING.md](TESTING.md) covers the failure modes the tests catch; the README's "Checks and tests" section lists the commands.

Keep this file current: a change that turns a rule off, adds an inline suppression, raises a baseline or lands a known warning updates it in the same pull request.

Errors fail a check; warnings are printed (and annotated in CI) but never fail one. The deploy job runs only after every CI job above has passed.

Every source folder has a formatter: Biome's on its scope, oxfmt (through Ultracite) on the site and the shell. Both use the same style, so code reads the same across the repository. Biome does not sort imports (its assist is off), so import order, and any side effects that depend on it, never changes on format. `.git-blame-ignore-revs` lists formatting-only commits; `git config blame.ignoreRevsFile .git-blame-ignore-revs` makes `git blame` skip them (GitHub does this automatically).

## Rules switched off in config

### Biome (`biome.json`)

| What | Files | Why |
| --- | --- | --- |
| Excluded from linting | `packages/ui/src/components/ui/*.tsx` (the vendored shadcn primitives listed in `files.includes`) | They must stay byte-identical to shadcn upstream; the install test checks this, so they are never edited or codemodded. |
| Excluded from linting | `**/routeTree.gen.ts` | Generated by TanStack Router. |
| Assist off | everything | Biome's assist (import sorting and similar code actions) would reorder code on save; formatting alone is enforced. |
| Rule added | `style/noRestrictedImports` on `import { z } from "zod"` | The named import stops zod tree-shaking and adds about 70 KB gzipped per screen; use `import * as z from "zod"`. |

### oxlint, site (`apps/www/oxlint.config.mts`)

| Rule | Files | Why |
| --- | --- | --- |
| `react/iframe-missing-sandbox` | `components/screens/screen-runtime-preview.tsx`, `components/screens/screens-runtime-frame.tsx` | The preview iframes keep a sandbox (no top navigation) but need both `allow-scripts` and `allow-same-origin`: the runtime runs on its own origin and uses storage and the bridge's origin check. Chrome logs "can escape its sandboxing" for this combination; that is expected. Owner approved. |
| `react/no-clone-element`, `react/no-react-children` | `registry/primitives/animate/tabs/index.tsx`, `registry/primitives/effects/highlight/index.tsx` | Composition primitives: Tabs reads its panes to place them; Highlight wraps its items and supports `asChild`. Rewriting them would change the public API of installable registry items. Owner approved. |
| `jsx-a11y/prefer-tag-over-role` | `components/blocks/blocks-sidebar.tsx` | Kept as `role="dialog"`: a native `<dialog>` would change its exit animation and stacking. Owner approved. |

### oxlint, shell (`packages/shell-ui/oxlint.config.mts`)

| Rule | Files | Why |
| --- | --- | --- |
| `jsx-a11y/prefer-tag-over-role` | `src/components/ui/field.tsx`, `src/components/ui/input-group.tsx` | shadcn's Field and InputGroup use `role="group"` on a `div`, as upstream does; a `<fieldset>` around one field is the wrong semantics. Owner approved. |

### TypeScript

| Setting | Where | Why |
| --- | --- | --- |
| `skipLibCheck: true` | `tsconfig.base.json` | Skips type-checking dependencies' `.d.ts` files; this repository's own code is still checked strictly. |

## Known warnings (reported, not fixed)

| Warning | Where | Cause | Status |
| --- | --- | --- | --- |
| "GPU stall due to ReadPixels" | browser check, screen `auth/inset-login` | Chrome reads pixels back from that screen's WebGL canvas | harmless in tests; open |
| "Some chunks are larger than 500 kB after minification" | runtime build (Vite) | the runtime bundles every screen's dependencies | open; the per-screen bundle budget still applies |
| 'The semantics of the module level directive "use client" in ... may not be preserved when bundling' (`MODULE_LEVEL_DIRECTIVE`, about 430 per build) | runtime build (Vite) | Base UI, framer-motion and TanStack Router ship `"use client"` directives; the runtime is a client-rendered TanStack Start app with no React Server Components, so the bundler drops them and nothing changes | by design |
| "An iframe which has both allow-scripts and allow-same-origin ... can escape its sandboxing" | browser console on screen pages | required sandbox flags (see the iframe rule above) | by design |
| "[blocks preview] ... didn't report ready within 1.2 s; showing it anyway" | browser console on blocks pages | logged fallback when a block preview is slow to signal ready | by design |
| "[screens runtime] ... didn't report ready within 15 s ...; Showing a reload option." | browser console on screen pages | `ScreensRuntimeFrame` waits up to 15 s (`READY_TIMEOUT_MS`) for the runtime's `wf:ready`, then logs this and replaces the spinner with a Reload button; a late `wf:ready` still shows the preview. Seen only when the runtime is down, blocked or still compiling | by design |
| "Playwright's Chromium download failed or stalled" | CI annotation, browser, responsive and site jobs | `cdn.playwright.dev` stalls on GitHub runners; `scripts/ci-install-chromium.sh` falls back to Chrome for Testing storage | workaround in place; remove it when Playwright's own download works on GitHub runners |

## Decisions

- **Two linters, by owner decision.** Biome lints and formats the runtime, `packages/ui`, the bridge and `scripts/`; Ultracite (oxlint and oxfmt) lints and formats the site and the shell. Ultracite's strict preset on Biome's scope reports 8,623 errors (6,240 after its auto-fix, 4,686 of them in screens; measured 2026-11-22) where Biome reports none, so adopting it would rewrite most screens for little gain. TypeScript, the tests and the browser checks cover what neither linter can.
