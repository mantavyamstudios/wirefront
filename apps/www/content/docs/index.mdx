**Wirefront is a backend-agnostic catalogue of production-grade UI screens**, built on [shadcn/ui](https://ui.shadcn.com) with [Base UI](https://base-ui.com) and Tailwind CSS v4. Screens are organised by the experience they serve, from an app's frame to its accounts, data, activity, interactions and whole products. Install the one you need with the shadcn CLI, wire it to your backend and tweak it locally.

## What's a screen?

A screen is one self-contained page or panel. Each screen is a folder of three files that install into your project as source you own:

- **`view.tsx`**: the screen itself. Props in, UI out: no data, no fetching, no router.
- **`schema.ts`**: zod schemas, the types they infer and the screen's API contract (`defineApi`), the operations your backend answers.
- **`fixtures.ts`**: demo data that satisfies the schemas, for tests, stories and mocks.

## Three principles

### Adaptive

Screens fit your stack, not ours. One [`WirefrontProvider`](/docs/wiring#app-wide-setup) at the root of your app hands every screen your router's link component, your toast function, your locale, time zone and currency, copy overrides for every string, and a permission check. Screens use semantic theme tokens, so they follow your shadcn/ui theme in light and dark mode, and logical properties, so they mirror for languages of your required type (RTL/LTR).

### Dynamic

Data in, events out. Every list, user, number and label arrives through props, and every action leaves as a promise-returning callback: the screen shows pending state, applies optimistic updates where they are safe, rolls back and shows the error when an action fails. Lists are controlled through one query object (page, sort, filters, search) you send to your API. Raw values go in, formatted text comes out, in your user's locale.

### Responsive

From phone to wide desktop. Each screen is audited at 375, 768, 1024 and 1440 pixels wide, with tap targets, keyboard paths and reduced motion checked. Preview any screen in a phone, tablet or laptop frame before you install it.

## Production grade

Every screen passes the same checks before it ships:

- typechecked under the strictest template settings, with fixtures that satisfy its schemas;
- zero axe accessibility violations in every state it declares;
- wiring tests for what each action receives and what the screen shows on success, failure and thrown errors;
- installed and built in fresh Next.js, Vite and TanStack Start apps.

## How it's organised

Screens sit in kinds, and kinds sit in six groups. A screen's address follows the same path, `/{group}/{kind}/{screen}`:

- **Shells**: app frames and navigation.
- **Accounts**: identity, access and plan: auth, settings, profile, pricing.
- **Data**: reading and slicing numbers: dashboards, tables, charts, filters.
- **Activity**: things happening over time or between people: cards, timelines, calendars, threads.
- **Interaction**: how the UI asks, confirms, warns and guides: forms, modals, toasts, tours, empty states.
- **Products**: whole apps built from the pieces above: apps, AI, dev tools, personal, commerce.
